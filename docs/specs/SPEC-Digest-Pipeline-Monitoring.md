## Problem Statement

The digest pipeline has **zero redundancy**. When Dropper-Code hits Claude Code usage limits, 105+ users receive no digests. This is a silent product failure — no alerts, no fallback, no degraded mode.

**Current State:**
- 2/108 digests sent in 24h (PRD Section 8)
- Dropper-Code Claude limits reset Mar 20 3am UTC
- No human fallback when automation fails
- Users get silence instead of daily clarity

---

## Goals

1. **Detect** digest pipeline failures within 2 hours
2. **Alert** Joey via WhatsApp when stall detected
3. **Fallback** to human approval mode when automation fails
4. **Track** digest delivery metrics for accountability

---

## Proposed Architecture

### 1. Monitoring Endpoint
```
GET /api/admin/digest-status
Response:
{
  "users_eligible": 108,
  "digests_sent_24h": 2,
  "stalled_users": ["user_id_1", "user_id_2", ...],
  "last_successful_batch": "2026-03-17T14:23:00Z",
  "status": "stalled|healthy|degraded",
  "claude_quota_remaining": "0% (resets 2026-03-20 03:00 UTC)"
}
```

### 2. Alerting Flow
```
IF digests_sent_24h < (users_eligible * 0.8) AND last_alert > 2h:
  POST /hooks/agent
  {
    "type": "digest_stall_alert",
    "severity": "critical",
    "message": "🚨 DIGEST STALL: 105/108 users missed digests. Claude quota exhausted. [Approve degraded send]",
    "actions": ["approve_degraded_send", "ignore_until_reset"]
  }
```

### 3. Degraded Mode Template
- Simplified HTML (no Claude-generated insights)
- Uses cached user data from previous digests
- One-click approval via WhatsApp reply
- Falls back to plain text if HTML fails

### 4. Dashboard Integration
- Add digest health to `/api/ops/dashboard`
- Track: sent rate, stall events, fallback usage
- Alert history for post-mortems
